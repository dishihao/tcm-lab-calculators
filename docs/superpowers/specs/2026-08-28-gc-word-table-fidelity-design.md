# 气相含量测定 Word 原记录表格精确复刻设计

日期：2026-08-28  
状态：用户已最终确认，进入实施计划阶段

## 1. 目标

气相含量测定页面在选择具体品名、原料/成品记录和待测成分后，必须将该成分在源 Word 检验记录中对应的“对照品”表和“供试品”表按原结构、尺寸和视觉格式重建为可填写、可计算的 HTML 表格。

“精确复刻”包括：

- 表格固定宽度和左侧缩进；
- 列网格和每列宽度；
- 行数量、行顺序、行高和高度规则；
- 横向、纵向合并单元格；
- 单元格内边距；
- 四边边框的线型和粗细；
- 水平和垂直对齐；
- 固定文字、单位、换行和公式；
- 字体、字号、粗体、上下标和字符格式；
- 输入槽位、进样针数和自动计算结果位置。

浏览器和 Microsoft Word 的字体抗锯齿允许存在极小颜色差异，但表格几何尺寸、边框位置、文字位置、换行位置、单元格合并关系和业务字段位置必须一致。

## 2. 已确认的产品约束

- 只改气相含量测定的“对照品”和“供试品”两张表。
- 品名选择、记录选择、成分选择、标准规定、判定限度、计算公式、修约、结论等其他区域保持现有结构。
- 现有计算引擎继续使用，不因视觉复刻修改计算公式。
- 每份原料、成品、地区版和炮制版记录独立关联源表。
- 一份记录存在多个待测成分时，每个成分模板独立关联自己在 Word 中的对照品表和供试品表。
- 手机和窄屏保持 Word 原始表格宽度，不压缩、不重排、不改成卡片；用户通过横向滑动查看。
- 打印保留源表宽度、字号、边框、行高和列宽，不显示网页横向滚动条。
- 液相模板和自定义模板继续使用当前通用表格，不进入 Word 精确复刻路径。
- 源 Word 文件只读，任何提取过程都不得修改、保存或重命名源文件。

## 3. 范围

当前气相数据包含：

- 14 个品名；
- 28 份原料/成品记录，其中原料 14 份、成品 14 份；
- 33 个气相待测成分模板；
- 33 个对照品表映射；
- 33 个供试品表映射。

现有 28 个 `recordKey` 全部进入审计：

`patchouli-raw`、`patchouli-finished`、`mugwort-raw`、`mugwort-finished`、`star-anise-raw`、`star-anise-finished`、`mint-raw`、`mint-finished`、`clove-raw`、`clove-finished`、`cardamom-raw`、`cardamom-finished`、`dendrobium-raw`、`homalomena-raw`、`homalomena-finished`、`amomum-raw`、`amomum-finished-national`、`amomum-finished-shanghai`、`amomum-finished-beijing`、`fennel-raw`、`fennel-finished`、`fennel-salted-finished`、`brucea-raw`、`brucea-finished`、`flax-raw`、`elsholtzia-raw`、`elsholtzia-finished`、`pine-raw`。

不在本次范围内：

- 重做液相记录表格；
- 修改任何含量计算公式；
- 修改标准规定和判定限度；
- 修改显微、薄层、理化、杂质、水分、灰分、浸出物、二氧化硫或温湿度页面；
- 将源 Word 文档本身发布为网页附件；
- 自动猜测无法确认的业务字段。

## 4. 源文件权威与读取策略

源 Word 检验记录是表格排版的唯一权威。现有 `mode`、`dry`、`tableLayout` 等字段仅用于计算或旧兼容逻辑，不能用于推测精确表格。

读取统一通过 Windows Microsoft Word COM：

1. 以只读方式打开源 `.doc` 或 `.docx`。
2. 如果文件扩展名与内部格式不一致，将文件复制到系统临时目录并以临时 `.doc` 副本只读打开。
3. 不调用源文档的 `Save`、`SaveAs` 或任何写入操作。
4. 读取完成后关闭文档和 Word 实例并删除临时副本。
5. 提取失败时记录文件、表格和错误原因，停止该模板发布，禁止套用相似记录。

表格结构优先读取 Word 为具体表格范围返回的 OOXML，以保留 `tblGrid`、`gridSpan`、`vMerge`、`tcW`、`trHeight`、`tcMar`、边框、段落和文字区间格式。旧 `.doc` 先由 Word 打开，再读取所选表格范围的 OOXML，网站工具不直接解析旧二进制文件。

## 5. 模板到源表的明确映射

为每个气相成分模板建立人工核对的清单：

```js
{
  templateId: "mugwort-eucalyptol",
  recordKey: "mugwort-raw",
  sourceFile: "041艾叶原料检验记录1.doc",
  referenceTableIndex: 7,
  sampleTableIndex: 8
}
```

同一记录中的第二个成分使用自己的表格编号：

```js
{
  templateId: "mugwort-borneol",
  recordKey: "mugwort-raw",
  sourceFile: "041艾叶原料检验记录1.doc",
  referenceTableIndex: 9,
  sampleTableIndex: 10
}
```

运行时布局以 `template.id` 为主键。`recordKey` 只用于归组和记录来源，不能替代成分模板映射。

生成器必须校验：

- 33 个气相模板 ID 全部存在且唯一；
- 每个模板恰好有一个对照品表和一个供试品表；
- 表格编号在源文件中存在；
- 表格固定文字包含与待测成分相符的关键字段；
- 映射清单不存在未使用或重复条目。

## 6. 布局数据结构

生成的公开网页资源保存结构化布局，不保存 Word 二进制文件或内部验证截图。资源文件固定为 `assets/gc-record-table-layouts.js`。

每个模板布局包含：

```js
{
  templateId: "clove-eugenol-finished",
  recordKey: "clove-finished",
  sourceFile: "14701丁香成品检验记录（国炮）3.doc",
  referenceTable: {
    widthPt: 468.0,
    indentPt: 0,
    columnsPt: [180.0, 288.0],
    rows: [],
    cells: []
  },
  sampleTable: {
    widthPt: 468.0,
    indentPt: 0,
    columnsPt: [180.0, 144.0, 144.0],
    rows: [],
    cells: []
  }
}
```

行数据保存高度、最小/固定高度规则和分页属性。单元格保存网格位置、`rowSpan`、`colSpan`、四边边框、内边距、对齐和内容块。文字内容按段落和 run 拆分，保留字体、字号、粗体、上下标、换行和字符间距。

结构完全相同的底层表格允许按内容哈希去重，但每个模板仍保留自己的来源、表格编号和布局引用。任何去重都必须以全部结构和格式属性完全相同为前提，不能只比较字段名称。

## 7. 业务字段映射

空白单元格没有可靠业务语义，必须以人工确认的字段映射补充：

```js
{
  cellId: "reference-r5c2",
  role: "input",
  field: "assay.Cref",
  inputMode: "decimal"
}
```

自动输出使用 `role: "output"`，例如 `assay.out.Aref`。多针进样采用 `input-group`，明确保存字段数组、各槽位相对宽度和间距。

映射必须覆盖源表实际需要的：批号、纯度、来源、干燥条件、浓度、进样量、水分、取样量、稀释倍数、内标物和待测物峰面积、平均峰面积、RSD、校正因子、单份含量、相对偏差、平均含量及总量结果。

无法确认含义的空白单元格标记为审核错误，不生成输入框。每个业务字段在同一模板中只能映射一次；同一个输出不能同时写入多个未经明确批准的单元格。

## 8. HTML 渲染

新增独立的 Word 表格渲染器，只供已选择的气相模板调用。渲染器输入是一张结构化表格，输出固定宽度 HTML `<table>`：

- 使用 `<colgroup>` 写入 Word 列网格宽度；
- 表格和列宽使用 CSS `pt`，避免重复像素换算；
- 使用 `table-layout: fixed`；
- 使用 `rowspan`、`colspan` 重建合并关系；
- 每个单元格写入明确的宽度、行高、内边距、边框和对齐；
- 每个文字 run 使用独立 `<span>` 保存字体、字号、粗体和上下标；
- 保留源记录固定换行；
- 不允许浏览器自动均分列宽或缩小字号。

可填写值直接放入源表空白单元格，不在表格外新增第二套输入区。输入控件背景透明、无额外边框，尺寸受单元格约束；屏幕聚焦提示仅用于操作，打印时移除。自动计算结果写入源记录相应结果单元格。

现有 `data-k`、输出 ID、模板快照、初始化和计算函数继续使用。改变的是控件和结果出现的位置，不是状态键或计算逻辑。

## 9. 多端与打印

网页外层使用固定宽度滚动容器：

```html
<div class="word-table-scroll">
  <table class="word-record-table">...</table>
</div>
```

手机和窄屏：

- 表格保持源 Word 宽度；
- `overflow-x: auto`；
- 不缩放、不折叠、不隐藏列、不切换卡片布局；
- 品种和模板信息位于滚动区外。

打印：

- 隐藏网页选择区、按钮和焦点提示；
- 移除滚动容器裁切和滚动条；
- 保留 Word 表格磅值宽度、列宽、行高、字体和边框；
- 不放大到网页可用宽度；
- 当前 28 份源记录的两张表均按 A4 纵向表格宽度输出，不自动切换为横向页面。

## 10. 状态切换

选择气相模板时：

1. 保存当前模板全部输入状态。
2. 根据新 `template.id` 读取精确布局。
3. 重建对照品表和供试品表。
4. 恢复新模板以前填写的数据。
5. 重新计算并将结果写入布局指定的输出单元格。

初始化只删除当前模板的可填写值和计算结果，保留品种、模板、源固定文字和布局。液相、自定义模板和其他项目保持原行为。

## 11. 提取与验证产物

内部验证阶段为每个气相成分模板生成：

- 源文件及表格编号清单；
- 提取后的结构数据；
- 源 Word 对照品表和供试品表截图；
- 网页对照品表和供试品表截图；
- 统一 DPI 后的叠加图或差异图；
- 结构审计结果；
- 字段映射审计结果。

验证截图和差异图只保存在本地临时或忽略目录，不加入公开网页资源。

源 Word 截图通过将目标表格复制到临时 Word 对照文档并导出 PDF/PNG 生成。网页截图通过固定 Chrome 版本、固定设备缩放和固定页面缩放生成。比较时统一 DPI。

## 12. 验收标准

### 12.1 结构验收

- 33 个模板全部存在精确布局；
- 33 对表格映射无缺失、无重复；
- 表格总宽度、缩进、列宽和行高与源 Word 一致；
- 行列、合并关系无重叠、无空洞；
- 固定文字、单位、针数、上下标和公式逐项一致；
- 边框、内边距、对齐、字体和字号均有明确来源；
- 所有必需输入和输出字段位置明确且唯一。

### 12.2 视觉验收

- 源 Word 与网页的表格外边框位置一致；
- 所有横线和竖线位置一致；
- 合并单元格范围一致；
- 文字基线和换行位置一致；
- 不存在裁切、重叠或单元格撑开；
- 允许字体抗锯齿颜色差异，不允许结构或文字位置偏移。

### 12.3 交互验收

- 33 个气相成分模板均能正常打开；
- 切换模板同步切换两张表；
- 原料、成品、地区版和炮制版不混用布局；
- 多成分记录关联正确表格对；
- 输入、自动计算、数据隔离、恢复和初始化正常；
- 手机端保持固定宽度并可横向滑动；
- 打印不改变表格排版；
- 液相和全部其他项目回归通过；
- 页面无脚本错误。

## 13. 阻断条件

以下任一情况阻止提交和推送：

- 源 Word 文件无法读取；
- 某个模板找不到明确的两张表；
- 表格 OOXML 无法重建合并关系；
- 业务字段位置无法确认；
- 结构审计失败；
- Word 与网页出现边框、文字或换行偏移；
- 任何模板脚本报错；
- 液相或其他项目回归失败。

不得用相似品种、同名成品/原料或通用表格替代失败记录。遇到阻断项时必须报告源文件、成分模板、表格编号和具体差异。

## 14. 实施边界

实施阶段采用测试驱动开发：先建立会因当前通用表格而失败的结构与浏览器测试，再实现提取器、布局资源和渲染器。完成后进行全量结构审计、33 模板浏览器验证、源 Word/网页视觉对比、全项目回归和独立代码审查。

全部验证通过后，按照本仓库既定约定提交并直接推送到 `main`。
